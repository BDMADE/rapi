# Security & Bug Tracker (Phase 0 Audit)

All security issues identified during the Phase 0 audit and their verified fixes are tracked below.

| ID | Severity | Category | Affected File(s) | Issue Description | Fix Applied | Status |
|---|---|---|---|---|---|---|
| SEC-001 | High | Secrets Management | `config/default.toml`, `crates/cms-core/src/config.rs`, `docker-compose.yml` | Hardcoded placeholder `JWT_SECRET` was accepted silently on startup, enabling trivial JWT forgery if deployed without overriding env vars. | Removed static secret from `config/default.toml`; generated ephemeral 32-byte random secret in dev; enforced fail-fast `AppConfig::validate()` (>=32 chars, blocks known placeholders) in `production`; required `${JWT_SECRET:?}` in `docker-compose.yml`. | Fixed |
| SEC-002 | High | Network / Data Exposure | `docker-compose.yml` | Redis was published unauthenticated on `0.0.0.0:6379`, exposing session tokens, rate limits, cache entries, and background job queues. | Removed host port exposure so Redis stays internal to the Compose network, enabled `--requirepass ${REDIS_PASSWORD:?}`, authenticated `REDIS_URL`, and added `cap_drop: [ALL]` + `no-new-privileges`. | Fixed |
| SEC-003 | High | Supply Chain (Frontend) | `web/package.json`, `web/package-lock.json` | `npm audit` reported 4 vulnerabilities: `zod <4.6.6` (High memory-exhaustion DoS `GHSA-mrhx-c7xc-m3w5`), `tinypool <=2.1.1` via `vitest` (2 Critical prototype pollution → RCE), and `@vitest/mocker <=4.1.11` (Moderate path traversal / code injection). | Upgraded `zod` to `^4.6.7`, `@hookform/resolvers` to `^5.2.2`, and `vitest` to `^5.1.2`; verified `npm audit` reports 0 vulnerabilities. | Fixed |
| SEC-004 | Medium | Container Hardening | `Dockerfile`, `docker-compose.yml` | Runtime Docker image executed `rapi` as `root` (`uid=0`) and included unnecessary `sqlite3` CLI tooling. | Removed `sqlite3` CLI from runtime image, created dedicated non-root system user `rapi` (`uid 10001`), set `USER rapi`, and added `read_only: true`, `tmpfs: [/tmp]`, `cap_drop: [ALL]`, and `no-new-privileges:true` in Compose. | Fixed |
| SEC-005 | Medium | Third-Party Script / XSS | `crates/cms-api/src/routes.rs` | `/docs` loaded unpinned `https://unpkg.com/swagger-ui-dist@5` JS/CSS without SRI hashes on the CMS origin with `persistAuthorization: true` storing bearer tokens in `localStorage`. | Replaced external CDN Swagger UI with a self-contained zero-CDN OpenAPI viewer served directly from Rust, removed `localStorage` token persistence, and disabled `/docs` + `/openapi.json` by default in `production` (`ENABLE_DOCS=false`). | Fixed |
| SEC-006 | Medium | HTTP Hardening & CORS | `crates/cms-api/src/routes.rs` | `build_cors_layer` failed open to `allow_origin(Any)` when `CORS_ORIGINS` was empty/invalid and used `allow_headers(Any)`; router lacked security headers, body size cap, and request timeout. | Switched CORS to fail-closed with explicit header allowlist (`Authorization`, `Content-Type`, `Accept`, `X-Request-Id`); added `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `DefaultBodyLimit` (10 MB), and `TimeoutLayer` (30s). | Fixed |
| SEC-007 | Medium | Information Disclosure | `crates/cms-api/src/routes.rs` | `/admin/system/overview` exposed internal counts (`adminUsers`, `webhooks`, `pendingJobs`, backend topology, uptime) without authentication. | Blocked unauthenticated access to `/admin/system/overview` with `401 Unauthorized` in `production` mode (to be backed by Admin JWT middleware in Phase 1) while keeping development DX intact. | Fixed |
| SEC-008 | Low | Cache / Session Expiry | `crates/cms-core/src/runtime.rs` | `InMemoryCacheBackend::set()` ignored the per-entry `ttl` parameter and kept all keys for 3600s, which would extend short-lived rate limits and reset tokens in local mode. | Stored per-entry `expires_at: Option<Instant>` checked and invalidated on `get()`, with unit test verifying sub-second expiry behavior. | Fixed |
| SEC-009 | Low | Secret Leakage in Logs | `crates/cms-core/src/config.rs` | Derived `#[derive(Debug)]` on `AppConfig` printed `jwt_secret` and embedded `redis_url` passwords in plaintext if logged. | Implemented custom `fmt::Debug` redacting `jwt_secret` (`[REDACTED]`) and masking credentials inside `redis_url`, verified via unit test. | Fixed |
| SEC-010 | Low | Response Amplification | `crates/cms-api/src/routes.rs` | `not_found_handler` reflected arbitrarily long request paths verbatim in error JSON responses. | Truncated reflected route paths in `404` error messages to 128 characters. | Fixed |


## Phase 1 Audit (Auth, RBAC & Tokens)

| ID | Severity | Category | Affected File(s) | Issue Description | Fix Applied | Status |
|---|---|---|---|---|---|---|
| BUG-P1-01 | High | Token Revocation | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | Revoked API/Admin tokens remained valid in `CacheBackend` for up to 60s until cache TTL expired. | `AuthRepository::delete_token` now returns `access_key_hash` and `AuthService::delete_token` immediately evicts `rapi:token:<hash>` from cache. | Fixed |
| BUG-P1-02 | High | Session Security | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | Deleting/deactivating an admin user or changing their password left existing refresh tokens active in `sessions`. | Added `delete_sessions_for_user("admin", id)` called on password change, deactivation, and user deletion. | Fixed |
| BUG-P1-03 | High | Race Condition (TOCTOU) | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | First-admin registration checked `COUNT(*)` on reader pool before inserting on writer pool, risking dual Super Admins under concurrent requests. | Replaced with transactional `create_first_admin_atomic` verifying `COUNT(*) == 0` inside the single-writer transaction. | Fixed |
| BUG-P1-04 | High | Brute-Force Bypass | `crates/cms-api/src/auth.rs` | Login rate-limit key coupled IP (`X-Forwarded-For`) with email, allowing attackers to bypass limits by spoofing `X-Forwarded-For`. | Added an independent per-email rate-limit bucket (`login_email`, 10/min) alongside per-IP throttling (`login_ip`, 30/min). | Fixed |
| BUG-P1-05 | Medium | Auditability | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | `api_tokens.last_used_at` and `admin_tokens.last_used_at` were never updated on token authentication. | Added `touch_token_last_used` triggered on token resolution (bounded by the 60s cache window). | Fixed |
| BUG-P1-06 | Medium | Privilege Lockout | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | The sole active Super Admin could be demoted, deactivated, or deleted, permanently locking out recovery. | Added `count_active_super_admins` guard returning `400 BadRequest` before demoting, deactivating, or deleting the last active Super Admin. | Fixed |
| BUG-P1-07 | Medium | Frontend UX / Tokens | `web/src/features/settings/tokens-page.tsx` | Navigating between `/settings/api-tokens` and `/settings/admin-tokens` did not sync tab state, and `custom` tokens had no permission picker in the modal. | Synced `kind` with `defaultKind` via `useEffect` and added interactive permission checkboxes from `/admin/permissions/catalog` when `type === "custom"`. | Fixed |
| BUG-P1-08 | Medium | Frontend Auth Concurrency | `web/src/lib/api.ts`, `web/src/features/users-roles/users-roles-page.tsx` | Parallel `401` responses raced single-use refresh-token rotation and forced logouts; Admin Users table lacked an active/inactive toggle. | Deduplicated concurrent refreshes via singleton `inflightRefresh` promise in `api.ts`; added inline Active/Inactive `Switch` wired to `PUT /admin/users/{id}`. | Fixed |
| BUG-P1-09 | Low | Error Handling | `crates/cms-db/src/auth.rs` | Creating or updating a user with a non-existent `roleId` returned `500 Internal Server Error` from SQLite FK violation. | Mapped SQLite `FOREIGN KEY` violations on `admin_user_roles` to `400 BadRequest`. | Fixed |
| BUG-P1-10 | Low | Data Integrity | `crates/cms-db/src/auth.rs`, `crates/cms-services/src/auth.rs` | `PUT /admin/roles/{id}/permissions` inserted orphan permission rows for non-existent role IDs. | Added `role_exists` check returning `404 NotFound` when the target role does not exist. | Fixed |


## Phase 2 Audit (Schema Engine & Content-Type Builder)

| ID | Severity | Category | Affected File(s) | Issue Description | Fix Applied | Status |
|---|---|---|---|---|---|---|
| BUG-P2-01 | High | Orphan Data Integrity | `crates/cms-db/src/schema_engine.rs` | Removing a `Relation` or `Media` field left orphan rows in `content_relations`/`upload_file_relations`, and deleting a content type left orphan `content_versions` and `upload_file_relations`. | Added `cleanup_removed_virtual_fields` inside `update_schema` and full `content_versions` + `upload_file_relations` cleanup inside `delete_schema` transactions. | Fixed |
| BUG-P2-02 | High | Schema Graph Cycle | `crates/cms-services/src/schema.rs` | Direct component self-embedding was blocked, but transitive cycles (`A -> B -> A`) were allowed, risking infinite recursion in dynamic forms and GraphQL SDL generation. | Implemented DFS `detect_component_cycle` rejecting any transitive component cycle with `400 ValidationError`. | Fixed |
| BUG-P2-03 | High | DDL Error Mapping | `crates/cms-db/src/schema_engine.rs` | Adding `unique: true` to an existing field with duplicate rows surfaced SQLite `UNIQUE constraint failed` as `500 Internal Server Error`. | Mapped `UNIQUE constraint failed` in `execute_and_log_ddl` to `409 Conflict` with an actionable message. | Fixed |
| BUG-P2-04 | High | Route Collision | `crates/cms-services/src/schema.rs` | Content types could claim reserved built-in API slugs (`upload`, `auth`, `users`, `graphql`, `admin`, `health`, `ready`, `docs`). | Added `RESERVED_API_SLUGS` check returning `400 ValidationError`. | Fixed |
| BUG-P2-05 | Medium | Field Validation | `crates/cms-services/src/schema.rs` | Invalid validation bounds (`minLength > maxLength`, `min > max`) and unbounded regex patterns were saved unchecked. | Added bounds checks (`minLength <= maxLength`, `min <= max`) and 256-char regex cap in `normalize_and_validate_schema`. | Fixed |
| BUG-P2-06 | Medium | DDL Migration Noise | `crates/cms-db/src/schema_engine.rs` | Editing non-DDL metadata (`displayName`, `description`) emitted redundant `CREATE INDEX IF NOT EXISTS` statements and logged spurious `alter_add_columns` entries in `schema_migrations`. | Only emit index/alter DDL and log `alter_add_columns` when physical columns or new `unique` constraints actually change. | Fixed |
| BUG-P2-07 | Medium | Frontend Builder UX | `web/src/features/content-type-builder/builder-page.tsx` | Switching schemas discarded unsaved changes silently, duplicate/invalid field names could crash React table keys, and clicking Delete dropped the SQLite table without confirmation. | Added `selectSchemaSafely` unsaved-changes guard, client-side identifier & duplicate-name validation in `commitFieldModal`, and a destructive confirmation `Dialog` before dropping schemas. | Fixed |
| BUG-P2-08 | Low | Component Metadata | `crates/cms-services/src/schema.rs` | Components created via API without `draftAndPublish: false` defaulted to `true` via serde default. | Forced `draft_and_publish = false` and `i18n_enabled = false` for `ContentKind::Component` in `normalize_and_validate_schema`. | Fixed |
